# AWS Transform Issues and Required Fixes

This document outlines the issues found in the code generated by AWS Transform when converting Bob's Used Bookstore from SQL Server to PostgreSQL, and the fixes required to make the application work.

## Overview

AWS Transform successfully converted the application from SQL Server to PostgreSQL, but failed to handle two critical issues that prevented the application from running properly.

---

## Issue 1: Calculated Properties Incorrectly Mapped to Database Columns

**File:** `app/Bookstore.Data/ApplicationDbContext.cs`

**Location:** Order entity configuration in `OnModelCreating()` method

### Problem Description

AWS Transform attempted to map calculated/computed properties (`Tax`, `SubTotal`, `Total`) as database columns. However, these properties in the `Order` entity are:
- Read-only (no setters)
- Marked with `[NotMapped]` attribute
- Calculated from other properties at runtime

### Original Code (Generated by AWS Transform)

```csharp
// Order entity configuration
modelBuilder.Entity<Order>(entity =>
{
    entity.ToTable("orders", "bobsusedbookstore_dbo");
    entity.Property(e => e.CustomerId).HasColumnName("customerid");
    entity.Property(e => e.AddressId).HasColumnName("addressid");
    entity.Property(e => e.DeliveryDate).HasColumnName("deliverydate");
    entity.Property(e => e.OrderStatus).HasColumnName("orderstatus");
    entity.Property(e => e.Tax).HasColumnName("tax");              // ❌ WRONG
    entity.Property(e => e.SubTotal).HasColumnName("subtotal");    // ❌ WRONG
    entity.Property(e => e.Total).HasColumnName("total");          // ❌ WRONG
    entity.Property(e => e.Id).HasColumnName("id");
    entity.Property(e => e.CreatedBy).HasColumnName("createdby");
    entity.Property(e => e.CreatedOn).HasColumnName("createdon");
    entity.Property(e => e.UpdatedOn).HasColumnName("updatedon");

    // Preserve existing relationship
    entity.HasOne(x => x.Customer).WithMany().OnDelete(DeleteBehavior.Restrict);
});
```

### Fixed Code

```csharp
// Order entity configuration
modelBuilder.Entity<Order>(entity =>
{
    entity.ToTable("orders", "bobsusedbookstore_dbo");
    entity.Property(e => e.CustomerId).HasColumnName("customerid");
    entity.Property(e => e.AddressId).HasColumnName("addressid");
    entity.Property(e => e.DeliveryDate).HasColumnName("deliverydate");
    entity.Property(e => e.OrderStatus).HasColumnName("orderstatus");
    entity.Property(e => e.Id).HasColumnName("id");
    entity.Property(e => e.CreatedBy).HasColumnName("createdby");
    entity.Property(e => e.CreatedOn).HasColumnName("createdon");
    entity.Property(e => e.UpdatedOn).HasColumnName("updatedon");
    entity.Ignore(e => e.Tax);        // ✅ FIXED - Explicitly ignore calculated property
    entity.Ignore(e => e.SubTotal);   // ✅ FIXED - Explicitly ignore calculated property
    entity.Ignore(e => e.Total);      // ✅ FIXED - Explicitly ignore calculated property

    // Preserve existing relationship
    entity.HasOne(x => x.Customer).WithMany().OnDelete(DeleteBehavior.Restrict);
});
```

### Explanation of Fix

The fix removes the incorrect column mappings for `Tax`, `SubTotal`, and `Total`, and explicitly tells Entity Framework to ignore these properties using the `Ignore()` method. This is necessary because:

1. These properties are defined in the `Order` class as:
   ```csharp
   [NotMapped]
   public decimal Tax => SubTotal * 0.1m;
   
   [NotMapped]
   public decimal SubTotal => OrderItems.Sum(x => x.Book.Price);
   
   [NotMapped]
   public decimal Total => SubTotal + Tax;
   ```

2. They have no setters (read-only)
3. They are calculated at runtime from other data
4. They should not be persisted to the database

### Error Caused

Without this fix, the application crashes on startup with:

```
System.InvalidOperationException: No backing field could be found for property 'Order.SubTotal' and the property does not have a setter.
```

## Issue 2: Database Initialization Logic Prevents Schema Creation

**File:** `app/Bookstore.Web/Startup/MiddlewareSetup.cs`

**Location:** `ConfigureMiddlewareAsync()` method

### Problem Description

AWS Transform kept the original conditional logic that only creates the database schema if the connection fails. This logic works for SQL Server LocalDB (which auto-creates databases), but fails for PostgreSQL in containers where the database exists but is empty.

### Original Code (Generated by AWS Transform)

```csharp
// Create/update the database
using (var scope = app.Services.CreateAsyncScope())
{
    var context = scope.ServiceProvider.GetService<ApplicationDbContext>()!;
    
    if (!await context.Database.CanConnectAsync())  // ❌ WRONG - Only creates if connection fails
    {
        await context.Database.EnsureCreatedAsync();
    }
}
```

### Fixed Code

```csharp
// Create/update the database
using (var scope = app.Services.CreateAsyncScope())
{
    var context = scope.ServiceProvider.GetService<ApplicationDbContext>()!;
    await context.Database.EnsureCreatedAsync();  // ✅ FIXED - Always ensure schema exists
}
```

### Explanation of Fix

The fix removes the conditional check and always calls `EnsureCreatedAsync()`. This method is idempotent - it will:
- Create the schema if it doesn't exist
- Do nothing if the schema already exists
- Not drop or modify existing data

The original logic failed because:
1. PostgreSQL container starts with an empty `postgres` database
2. Connection succeeds (database exists)
3. But no tables exist yet
4. Application tries to query non-existent tables and crashes

### Error Caused

Without this fix, the application crashes when trying to access any page with:

```
PostgresException: 42P01: relation "bobsusedbookstore_dbo.orderitem" does not exist
```

## Summary

### What AWS Transform Did Successfully ✅

- Converted database provider from SQL Server to PostgreSQL
- Changed `UseSqlServer()` to `UseNpgsql()`
- Updated connection string builder from `SqlConnectionStringBuilder` to `NpgsqlConnectionStringBuilder`
- Converted all table and column names to lowercase with schema `bobsusedbookstore_dbo`
- Updated package references (removed SQL Server, added Npgsql)
- Preserved all entity relationships and constraints

### What AWS Transform Failed to Handle ❌

1. **Calculated Properties**: Did not recognize that `Tax`, `SubTotal`, and `Total` are computed properties that should not be mapped to database columns
2. **Database Initialization**: Did not adapt the database initialization logic for containerized PostgreSQL environments where the database exists but is empty

### Impact

Both issues are critical and prevent the application from running. They must be manually fixed after AWS Transform completes the conversion.

---

## Recommendations for AWS Transform Improvements

1. **Detect `[NotMapped]` attributes**: AWS Transform should recognize properties marked with `[NotMapped]` and automatically use `Ignore()` in the entity configuration
2. **Detect read-only properties**: Properties without setters that are calculated should be automatically ignored
3. **Update initialization logic**: For PostgreSQL conversions, remove conditional checks around `EnsureCreatedAsync()` since PostgreSQL doesn't auto-create databases like SQL Server LocalDB
